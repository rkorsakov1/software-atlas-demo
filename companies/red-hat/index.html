Moats

Seven axes, each scored 0–5. These are Modeled judgments made in this project against the published rubric, not measurements. The rationale below says why.

  • Network 3ISVs certify against RHEL because enterprises run it, and enterprises run it because ISVs certify against it.
  • Switching 4certified application stacks and a trained administrator population make a distribution change a multi-year programme.
  • Scale 3maintaining and back-porting a decade-long support stream is a fixed cost a free rebuild cannot fund.
  • Data 1support telemetry informs engineering rather than product quality.
  • Brand 5'enterprise Linux' means Red Hat to a procurement department.
  • Ecosystem 5RHCE certification is a taught career path, and ISVs and integrators build standalone businesses on it.
  • Regulatory 4government and sector certifications are granted against specific RHEL builds, which makes alternatives a compliance risk.
Network effects3 / 5
Cross-side effects exist within a customer: more colleagues on the product raise its value to each of them.
Switching costs4 / 5
Deep customisation, bespoke integrations and certified administrators make replacement a multi-year programme.
Scale economies3 / 5
Large fixed investments (data centres, model training, compliance) amortise over a base a subscale rival cannot match.
Data advantage1 / 5
Usage data informs the roadmap but does not make the product itself better for the customer.
Brand5 / 5
The brand is the category noun, and buyers describe the job using the vendor's name.
Ecosystem5 / 5
The ecosystem is a labour market and a curriculum: skills are taught, hired for and career-defining, which locks in the next generation of buyers.
Regulatory4 / 5
The vendor is named in or certified under regulation, so buyers in the sector face additional risk using an alternative.
